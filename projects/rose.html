01 / CUSTOMER ENGAGEMENT

ROSE AI Messenger Automation

An n8n workflow for incoming Messenger events, short AI-assisted customer responses, and platform API integration.

Real screenshot of the visible workflow editor. Credentials and customer messages are not shown.

The problem

Customers can send multiple Messenger messages in quick succession. A reply system needs to receive webhook events, preserve useful message context, avoid repetitive replies, and respond without fabricating prices or product claims.

How the system is structured

  • POST webhook receives incoming events; a separate GET verification branch is visible.
  • JavaScript processing and a message buffer organize the input.
  • A Wait node and debounce-check code are intended to consolidate rapid messages.
  • An HTTP node is configured to call Google Gemini; a second HTTP node targets Meta Graph API.
  • The instruction template accounts for image-presence flags, customer inquiries, pricing uncertainty, complaints, and escalation wording.

Evidence & limitations

The supplied n8n editor screenshot plus AI instruction template support the implementation description. Image flags alone do not prove image understanding.

Workflow configuration available; live end-to-end execution not independently verified. The code was developed with significant AI assistance. Descriptions here refer to visible implementation and do not imply independent production verification.

Next engineering improvements

  • Move API keys into managed n8n credentials and verify token rotation.
  • Add a real staff-handoff queue and a failure notification path.
  • Test the workflow using synthetic customer data before showing live results.
